# 01 总体架构与工程落地

> 依据：《法律实训数字平台系统 分工程功能需求规格说明书 V3.0》+《V3.0 功能点清单》
> 代码基线：`C:\code\legalTraining`（RuoYi 3.9.2 / Spring Boot 4 / Java 17 / MyBatis / Vue2 + Element UI）
> **已定决策 1**：公网展示端（C）、展厅（E4 → A 内）、学生端（B）均按文档要求独立成工程，本期不做"同包不同路由"的折中。
> **已定决策 2**：展厅走**纯网页版展示**，不引入 Three.js / WebGL / 全景拼接；展区以"头图 + 长页 + 热点 + 版式切换"实现沉浸感。
> **已定决策 3**：通知**只做站内信**，不接短信与微信，`ops_notification.channel` 固定 `inner`。

## 2. 四个交付件与代码落位

| 代号 | 交付件 | 代码位置 | 技术栈 | 部署边界 |
|---|---|---|---|---|
| A | 教学与管理 Web（E1/E2/E4/E8 门户页） | `legalTraining-ui`（既有） | Vue2 + Element UI（沿用，不迁移） | 校园内网 |
| B | 学生移动端（E3） | `lt-student-h5`（**新建**） | Vue3 + Vite + Vant | 公网 |
| C | 展厅展示端（E5/E6/E7） | `lt-exhibit`（**新建**） | Vue3 + Vite（纯网页，无三维引擎） | 公网 + CDN，现场 kiosk 同包 |
| D | 后端服务与开放接口 | `legalTraining-*`（既有 6 模块 + 新建 1 模块） | Spring Boot 4 / MyBatis | 内网，开放接口经 DMZ |

> **A 不迁移 Vue3**：Vue2 + Element UI 的表格/表单/审批是 E1、E2、E4 的主体，迁移收益低于风险。B、C 是新建工程，直接用 Vue3 + Vite —— 首屏体积和构建速度对公网端是硬指标。C 不引三维引擎后，首屏只有 HTML/CSS/图片，包体可压到 A 的一半以下。三端共用的是**接口契约**，不是组件。

### 2.1 后端：单应用 + 一个业务模块 + 三个领域包

```
legalTraining
├── legalTraining-admin        Web 层：controller（按域分包）+ 启动类 + 配置
│   └── com.legaltraining.web.controller
│       ├── edu/     E1/E2/E3 接口
│       ├── exh/     E4 接口 + 开放接口（/openapi/v1）
│       └── ops/     应用接入、通知、备份
├── legalTraining-business     【新增】业务层：domain / mapper / service
│   └── com.legaltraining.business
│       ├── edu/     教学业务服务
│       ├── exh/     展厅内容服务（@DS("exhibit") 指向独立 schema）
│       ├── ops/     运营服务
│       └── api/     跨域接口（edu↔exh 只经此包）
├── legalTraining-system       身份与权限服务（沿用）
├── legalTraining-common       工具、常量、异常、统一响应
├── legalTraining-framework    安全、拦截器、数据源、限流、幂等、开放接口网关
└── legalTraining-quartz       调度（Job 只做触发）
```

**依赖约束（ArchUnit 守住）**

1. `admin → business → common`，禁止反向。
2. `edu` 与 `exh` 只能经 `business.api` 互调，且只允许两条链：OP-02-05 推荐推送、OP-02-06 审核回写。
3. `system` 被所有域依赖，不反向依赖业务域。

### 2.2 三个前端工程各自独立

| | A 教学与管理 | B 学生端 | C 展厅展示端 |
|---|---|---|---|
| 仓库/目录 | `legalTraining-ui` | `lt-student-h5` | `lt-exhibit` |
| 构建 | vue-cli（现状） | Vite | Vite |
| UI 库 | Element UI | Vant | 自研组件（CSS 版式化，无 UI 框架） |
| 路由前缀 | `/admin` `/teacher` `/exhibit` `/portal` | `/`（单入口） | `/immersive` 长页、`/lite` 简版、`/kiosk` 终端 |
| 登录 | 账号密码 + 令牌 | 学号或统一身份认证 | 免登录（访客）/ 设备令牌（kiosk） |
| 调用的后端 | `/edu/**` `/exh/**` `/ops/**` | `/edu/**`（只读+提交） | `/openapi/v1/**` |
| 域名 | 内网 `lt.xxx.edu.cn` | 公网 `m.xxx.edu.cn` | 公网 `exh.xxx.edu.cn` |
| 发版 | 独立 | 独立 | 独立（含 CDN 刷新） |

**三条硬规则**

1. **C 只调 `/openapi/v1/**`**，不调内部接口 —— 这是"公网接口不直连教学库"的落地方式，也是测评边界的依据。
2. **B 不共享 A 的 session**，用同一套 `/auth` 令牌体系但独立域名，跨域走 CORS 白名单 + 令牌（不用 Cookie）。
3. **三端不共享组件库**，只共享 `docs/03-接口清单.md` 的契约与 `openapi.json`（后端 springdoc 生成）。

### 2.3 权限：两层校验

```
第一层（框架层）  角色 → 菜单/按钮权限点 → @PreAuthorize("@ss.hasPermi('edu:task:add')")
                 数据范围 sys_role.data_scope → @DataScope 拼 SQL
第二层（业务层）  BusinessScopeChecker：教师限本课程、学生限本人、
                 内容编辑/审核员：推荐人 ≠ 审核人（MG-02-02 硬约束）
```

角色：`admin / registrar / teacher / student / editor / auditor`；一人多角色由 `sys_user_role` 承担，权限并集沿用 RuoYi 现有实现。

### 2.4 状态机：集中定义、服务内迁移

第 6 章四条状态机收敛到 `TaskStateService` / `SubmissionStateService` / `RecommendationStateService` / `ExhibitStateService`，入参 `(id, action, operator, payload)`，非法迁移抛 `BizException`。状态值只存在 `sys_dict_data` 一处。

### 2.5 数据源：展厅独立 schema

| 数据源 | schema | 内容 | 访问方 |
|---|---|---|---|
| `master` | `legal_training` | `sys_*` + `edu_*` + `ops_*` | A、B、D |
| `exhibit` | `legal_exhibit` | `exh_*` | A（E4）、C、D |

- `business.exh` 的 Service 加 `@DS("exhibit")`（dynamic-datasource），`edu` 与 `exh` 之间**不做跨库事务**，靠 `api` 包的补偿与幂等表兜底；
- 开放接口的读请求全部走缓存，不回源教学库；
- 迁移时只需执行 `biz_schema.sql` 里 `exh_` 段到 `legal_exhibit` 库，无需改表结构（脚本已无物理外键、无跨域 join）。

### 2.6 定时任务（quartz）

| Job | 频率 | 需求 |
|---|---|---|
| `TaskDeadlineJob` | 每分钟 | 任务到截止、批量判逾期（6.1/6.2） |
| `SubmitOverdueJob` | 每小时 | 退回后超重交截止 |
| `TaskRemindJob` | 每小时 | NT-02 |
| `ExhibitPublishJob` | 每分钟 | EM-03-03，失败重试 3 次告警 |
| `DeviceOfflineJob` | 每小时 | TM-01-04、NT-12 |
| `AuditBacklogJob` | 每日 | NT-13 |
| `AccessStatJob` | 每日 01:00 | 明细 → `exh_access_daily` |
| `ExportAsyncJob` | 事件 | MG-04-01 大导出 |

### 2.7 文件与素材

- 教学附件 `attachment/{yyyyMM}/`，展项素材 `exhibit/{zoneId}/{itemId}/`，**分目录、分存储桶**；
- 对外只给签名地址；
- 视频转码状态驱动发布校验。

### 2.8 开放接口网关

`framework` 内 `OpenApiFilter`：`X-App-Id + X-Timestamp + X-Nonce + X-Sign(HMAC-SHA256)` → 校验 `ops_app_api` 授权 → `ops_app_ip` 白名单 → Redis 限流 → 异步写 `ops_call_log`。内部接口与开放接口**分两个 FilterChain**，不共用鉴权逻辑。

## 4. 已确认的决策（原 3 个待确认项）

| # | 决策 | 影响 |
|---|---|---|
| 1 | 公网展示端独立工程、独立测评范围 | C 单独仓库/域名/构建；只调开放接口；等保范围不含 A 代码 |
| 2 | 展厅独立 schema | `exh_*` 落 `legal_exhibit`，`business.exh` 加 `@DS`；跨域不做事务 |
| 3 | 学生端独立工程 | B 单独仓库/域名；令牌鉴权 + CORS 白名单，不共享 Cookie |

**由此增加的固定成本**：3 套构建流水线、3 套域名证书、3 份安全测试范围、跨域令牌联调；**换来的收益**：测评边界清晰、任一工程发版不影响其余两个、C 的大资源不拖慢 A 的首屏。
