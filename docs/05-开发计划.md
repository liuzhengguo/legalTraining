# 05 开发计划与分批

> 分批原则：按**交付包**切，不按工程切。基础包是一切的前提；教学包与展厅包可并行，但都要等基础包可登录。
> 工作量为人日参考值，含自测与联调，不含需求返工与客户验收时间。

---

## 1. 三批总览

| 批次 | 范围 | 功能点 | 前置 | 参考工作量 |
|---|---|---|---|---|
| 第一批 · 基础包 | 登录/角色/菜单/数据范围、门户、应用接入、学期与账号导入 | 14 + 组织管理 6 = 20 | 无 | 25~32 人日 |
| 第二批 · 教学包 | E1 其余、E2 全部、E3 全部 | 54 | 第一批 | 55~70 人日 |
| 第三批 · 展厅包 | E4 全部、E5/E6/E7 | 63 | 第一批（教学包的推荐链路需第二批先完成） | 70~90 人日 |

> 展厅包里的"成果审核 → 一键成展"依赖教学包的 `edu_recommendation` 与授权链路，所以第三批不能早于第二批的 **TC-05** 完成。若两个团队并行，接口（OP-02-05/06）先按本文档定义冻结，双方各自 Mock。

**按工程看工作量归属**（已定：B、C 独立成工程）

| 批次 | 工程 A（Vue2） | 工程 B（学生端 Vue3） | 工程 C（展厅 Vue3） | 工程 D（后端） |
|---|---|---|---|---|

| 第二批 | 课程、资源、任务、批阅、成绩、推荐、监管、导出 | 课程、任务、提交、成绩、展项联动 | — | 教学域全部 |

### 2.2 验收口径（可执行）

1. 五类角色各建一个账号，登录后落到的菜单与文档 2.5 矩阵一致；无权限视图直接 403，不出现空页面。
2. 1000 行含 20 行错误的导入文件：980 行入库、20 行给出行号与原因、无重复账号；失败率 >30% 整批回滚。
3. 一人给"教师 + 审核员"双角色，推荐一条成果时被拦截并提示互斥。
4. 转班后：历史提交仍归原班（默认视图），切"当前归属"后归新班。
5. 应用注册后调 `/openapi/v1/zones`：签名错 401、未授权接口 403、超配额 429。

4. 学生撤回后再提交，版本号 +1，教师端历史版本可查两个版本。
5. 成绩发布后更正：`edu_score_adjust` 有记录、学生收到 NT-07。
6. 导出 6 万行：接口立即返回任务 ID，完成后通知，`edu_export_log` 有完整筛选条件与条数。

### 4.2 验收口径

1. 发布校验：摘要 19 字 / 121 字均被拦；视频转码未完成被拦；展区未开放被拦。
2. 定时发布晚于当前 3 分钟被拦（需 ≥5 分钟）；调度失败重试 3 次后转"发布失败"并有告警。
3. 回退到 v3 后版本号为 v5（新版本），v3 快照仍在。
4. 已下架展项通过开放接口访问返回 **410** 且带下线说明；简版显示"内容已下线"页。
5. 审核员与推荐教师同一人时，"通过"按钮不可用并提示。
6. kiosk 断网：显示"离线模式"角标并按缓存播放；恢复后按 `publish-state` 增量更新。
7. 展厅端（E5/E6/E7）首屏**不加载任何三维资源**：构建产物中无 `three`/`webgl` 相关包，首屏请求只有 HTML/CSS/图片与 `/openapi/v1/zones`。
8. 展区版式切换：`layout` 改为 `timeline` 后刷新前台即按时间轴渲染，无需重新发布展项。

## 5. 建议的开发顺序与并行方式

```
第一批（1 人后端 + 1 人前端）
   └─ 模块骨架 → 建表 → 学期/班级/账号 → 导入 → 授权 → 门户 → 开放接入
第二批（2 后端 + 2 前端，可分课程/任务两条线并行）
   ├─ 线 A：课程 → 资源 → 任务发布 → 监管/导出
   └─ 线 B：提交 → 批阅 → 成绩 → 推荐/授权
第三批（2 后端 + 2 前端 + 1 前端做展示端，可与第二批尾部重叠）
   ├─ 线 A：展区/展项/素材 → 发布/版本 → 开放接口
   ├─ 线 B：审核/成展 → 分享/统计 → 设备/缓存
   └─ 线 C：网页长页 / 简版 / kiosk 三套版式（纯 HTML+CSS）
```

## 6. 六个风险点（前五项已决策关闭）

| # | 风险 | 状态 | 说明 |
|---|---|---|---|
| 1 | 公网展示端是否独立工程/独立测评 | ✅ **已定：独立工程** | C 单独仓库、域名、构建；只调 `/openapi/v1/**`；测评范围不含 A 代码 |
| 2 | 展厅是否独立 schema | ✅ **已定：独立库** | `exh_*` 落 `legal_exhibit`，`business.exh` 加 `@DS("exhibit")`；跨库不做事务 |
| 3 | 学生端是否独立域名 | ✅ **已定：独立工程** | B 单独仓库与域名，令牌 + CORS，不共享 Cookie |
| 4 | 三维展厅技术路线 | ✅ **已定：纯网页版，不做三维** | 展区用 `layout`（grid/flow/timeline）+ 头图 + 热点渲染，不引入 Three.js/WebGL/全景；`exh_zone` 无 `panorama` 字段 |
| 5 | 是否接短信/微信通知 | ✅ **已定：只做站内信** | `ops_notification.channel` 固定 `inner`，模板 `channels` 固定 `inner`；不接短信网关与微信模板消息，无需相应资质与费用 |
| 6 | 需求侧 4 个缺口（见 04 文档第 3 章） | ⬜ 待定 | 验收要点、权重与等级制冲突、410 与缓存冲突会在验收时爆 |

**新增的固定成本**（独立工程的代价，需计入报价）：3 套构建流水线、3 套域名与证书、3 份安全测试范围、跨域令牌联调、B/C 脚手架各 2~3 人日。
