# 02 数据库设计

> 脚本：`sql/biz_schema.sql`（建表）、`sql/biz_seed.sql`（字典 / 角色 / 菜单 / 通知模板 / 参数）
> 数据库：MySQL 8.0，`utf8mb4`，InnoDB，时间统一 `datetime`，时区 `Asia/Shanghai`
> 共 57 张业务表：`edu_` 33 张、`exh_` 15 张、`ops_` 9 张；框架表复用 RuoYi 的 `sys_*`，未做任何结构修改。

---

## 1. 命名与通用约定

| 约定 | 说明 |
|---|---|
| 表前缀 | `edu_` 教学业务 / `exh_` 展厅内容 / `ops_` 接入与运营。前缀即未来拆库边界 |
| 主键 | `{对象}_id`，`bigint` 自增；纯关联表用 `id` |
| 外键 | **不建物理外键**，靠服务层保证；理由：拆库、批量导入、归档回滚都会与外键冲突 |
| 状态字段 | 一律 `tinyint` + 注释，取值与需求第 6 章一一对应，中文标签在 `sys_dict_data` 的 `biz_*` 字典 |
| 软删除 | 主数据用 `del_flag`（0 存在 / 2 删除）；流水与留痕表不做软删 |
| 审计字段 | `create_by / create_time / update_by / update_time`，与 RuoYi BaseEntity 对齐 |
| 金额与分数 | `decimal(6,2)`，不用 float |
| 富文本 | `longtext`，存结构化 JSON 或 HTML，由前端渲染器决定（见 03 文档） |

## 3. 七个关键设计决策

### 3.1 "发生时归属"而不是"当前归属"

文档 MG-01-06 要求：转班只影响此后产生的数据，历史提交仍归原班。

落法：`edu_class_student` 用 `join_time / leave_time / is_current` 表达时段归属；所有成绩与进度查询默认按 `edu_task_participant`（发布时的快照）统计，而不是 join 当前班级。这样"默认发生时归属"是零成本，"切换当前归属视图"只是一次 `join is_current='1'` 的另一种 SQL。

### 3.2 状态镜像，避免跨表 sum

`edu_task_participant.submit_status / overdue_flag` 是 `edu_submission` 的状态镜像。原因：教师"待批列表"要按状态筛选上万分提交，直接 join 大表 + `group by` 会慢；写路径只有"提交/撤回/批阅/退回"四个点需要同步，用同一事务维护。

### 3.3 版本快照独立成表，不覆盖历史

| 场景 | 表 | 规则 |
|---|---|---|
| 学生重交 / 退回 | `edu_submission_version` | 每次提交写一条，版本号 +1，附件随版本存 |
| 展项发布 / 回退 | `exh_item_version` | 发布、回退都写快照；回退 = 用旧快照生成**新版本**，不覆盖（EM-03-05） |
| 成绩更正 | `edu_score_adjust` | 只记差异与原因，`edu_score` 保存现值 |

### 3.4 幂等三处硬要求

文档 11.3 要求"提交、发布、推送、设备激活"四类接口幂等：

| 接口 | 幂等键 | 落法 |
|---|---|---|
| 提交 | `uk_sub_task_user (task_id, user_id)` | 重复提交走"更新 + 版本 +1" |
| 发布 | `exh_item.version` + `exh_publish_job.uk_pj_item` | 同一展项只允许一个待执行定时任务 |
| 推送 | `edu_recommendation.rec_id` | 重复推送返回同一结果 |
| 设备激活 | `exh_device.uk_device_code` | 一个设备码只能激活一台设备 |

### 3.5 展项与素材的删除策略

- 素材 `exh_item_media.status=1` 逻辑删，物理文件由清理 Job 延迟 7 天删除（防止回退版本引用已删素材）；
- 展项 `del_flag=2` 仅对草稿允许；已发布展项只能"下架"，不做删除（否则已分享短链 404，而需求要求 410 + 下线页）。

### 3.6 展区"版式"存字段，不存三维场景

`exh_zone.layout` 取 `grid / flow / timeline` 三值，配 `bg_image` + `theme_color`，前端据此渲染。这样：

- 展厅端不需要任何场景文件（模型/全景图），`exh_zone` 也没有 `panorama` 字段；
- 新增一种展区只需加一个 `layout` 字典值和一段 CSS，不动表结构；
- 运营在 E4 里改版式即时生效，不需要重新"生成场景"。

代价是同一展区内不能自由摆位，只能靠统一的网格/流式规则——对图文型成果展示足够，对空间叙事型展区会偏弱。

### 3.7 字典与枚举单一来源

`sys_dict_data` 的 `biz_*` 字典是唯一中文来源，Java 侧枚举只保留 code 与迁移规则，不写中文标签——避免"后端写'已截止'、前端写'已关闭'"这类同名不同义。

## 5. 容量与索引

**估算（单校，5000 学生 / 300 教师 / 200 课程 / 每学期 20 任务）**

| 表 | 单学期增量 | 三年累计 | 结论 |
|---|---|---|---|
| `edu_submission` | 10 万 | 60 万 | 单表可承载，按 `task_id` 分区可延后 |
| `edu_submission_file` | 约 20 万 | 120 万 | 需按 `submission_id` 索引，附件在对象存储 |
| `edu_score` | 10 万 | 60 万 | 归档学期可迁历史库 |
| `exh_access_event` | 视终端数，日 1 万级 | 千万级 | **必须**按日聚合后清理明细（保留 90 天） |
| `ops_call_log` | 视外部调用 | 百万级 | 保留 180 天，按 `call_time` 分区 |

**必建索引已在脚本中给出**，重点三条：

1. `edu_task (status, deadline)` —— 截止判定 Job 每分钟扫，不能全表。
2. `edu_submission (task_id, status)` —— 待批列表。
3. `exh_item (status, publish_time)` —— 展示端只查已发布。

## 6. 库划分（已定：展厅独立库）

| schema | 含表 | 数据源名 | 访问方 | 说明 |
|---|---|---|---|---|
| `legal_training` | `sys_*`、`edu_*`(33)、`ops_*`(9) | `master` | A、B、D | 教学与身份主库 |
| `legal_exhibit` | `exh_*`(15) | `exhibit` | A(E4)、C、D | 展厅内容库，独立连接池 |

**执行方式**

```bash
# 1) 建两个库
CREATE DATABASE legal_training DEFAULT CHARSET utf8mb4;
CREATE DATABASE legal_exhibit  DEFAULT CHARSET utf8mb4;

# 2) 框架库进主库
mysql -u root -p legal_training < sql/legalTraining.sql
# 3) 业务库按前缀分两次导入（脚本内按 -- 段落切开即可）
mysql -u root -p legal_training < sql/biz_schema_edu.sql
mysql -u root -p legal_exhibit  < sql/biz_schema_exh.sql
mysql -u root -p legal_training < sql/biz_seed.sql
```

> `sql/biz_schema.sql` 保留为**单库版**（含全部 57 张表），便于开发机一次建好；生产按 `docs/06` 的执行清单拆两个库。脚本无物理外键、无跨域 join，拆开不需要改任何字段。

**跨库三条纪律**

1. 不做跨库事务：`edu` 与 `exh` 的写操作靠 `api` 包 + 幂等表（`edu_recommendation.push_status`）补偿；
2. 不跨库 join：`exh_review` 需要推荐信息时，由 `api` 包查 `edu` 侧再组装；
3. 开放接口读流量只打 `legal_exhibit`，不触达教学库。

**后续演进**

| 阶段 | 动作 | 前置条件 |
|---|---|---|
| 二期（多校） | `edu_*` 加 `tenant_id`，接多租户插件 | 需引入学校维度 |
| 归档 | 学期归档后 `edu_*` 冷数据迁 `*_history` | 依赖 `ops_archive_unfreeze` 的解冻机制 |

> 唯一要守住的：**不建物理外键、不跨域 join**。
