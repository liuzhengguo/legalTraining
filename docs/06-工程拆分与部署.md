# 06 工程拆分与部署

> 已定：A / B / C 三个前端各自独立仓库、独立构建、独立域名、独立发版；D 为后端服务。
> 本文给出每个工程的目录约定、启动方式、环境变量、构建与发布、以及跨域与鉴权口径。

---

```
                         ┌─────────────────────────────┐

                         └─────────────────────────────┘  │
                         ┌─────────────────────────────┐  │   HTTPS + Bearer Token
   公网      m.xxx.edu.cn │ B  学生移动端（Vue3+Vant）   │──┼──────────────┐
                         └─────────────────────────────┘  │              │
```

| 属性 | A | B | C |

| 框架 | Vue 2.7 + Element UI 2 | Vue 3 + Vite 5 + Vant 4 | Vue 3 + Vite 5（纯网页展示，无三维引擎） |
| 包管理 | npm | pnpm | pnpm |

## 2. 目录约定

### 2.1 B 学生移动端 `lt-student-h5`

```
lt-student-h5/
├── src/
│   ├── api/            course.js task.js submission.js score.js exhibit.js
│   ├── components/     卡片、倒计时、附件上传、状态标签
│   ├── layouts/        TabLayout.vue（底部四 Tab）
│   ├── pages/
│   │   ├── login/      学号登录
│   │   ├── course/     课程列表、课程主页
│   │   ├── task/       任务列表、任务详情、提交、退回重交
│   │   ├── score/      成绩与明细、异议申请
│   │   └── mine/       我的成果、授权确认、通知
│   ├── stores/         user.js task.js
│   ├── utils/          request.js（axios 封装 + token 注入）
│   └── main.js
├── .env.development / .env.production
└── vite.config.js
```

关键约束：
- **不引 Element UI**，表单与列表全部用 Vant；
- 提交页支持**草稿 localStorage 暂存**（断网/切后台不丢），与后端 `edu_submission` 草稿接口双向同步；
- 附件上传走分片（>20MB），失败可续传。

### 2.2 C 展厅展示端 `lt-exhibit`

```
lt-exhibit/
├── src/
│   ├── api/            zone.js item.js share.js device.js（全部 openapi）
│   ├── modes/
│   │   ├── immersive/  展区头图、热点层、长页版式（图墙/长页/时间轴）、展项浮层
│   │   ├── lite/       单列图文、懒加载、分享卡
│   │   └── kiosk/      轮播、超时回首页、离线角标、本地缓存
│   ├── engines/        layout.js（按 exh_zone.layout 选版式）、media.js（懒加载与降级）
│   ├── cache/          IndexedDB 封装（素材与内容清单）
│   ├── styles/         base.css（展区长页、三种版式、热点、卡片）
│   ├── utils/          request.js（AppID/设备令牌两种签名）
│   └── main.js（按路由/UA 选择 mode）
├── public/
├── preview/            zone-web.html（零依赖版式走查页，浏览器直接打开）
└── vite.config.js
```

关键约束：
- **三种模式共用一套内容接口**，只在渲染层分叉，不做三份内容副本（文档 9.6）；
- 首屏只请求 `/zones` + 当前展项摘要，正文图与视频延后加载；**不加载任何三维资源**；
- 弱网判定：首屏资源 >5s 或连续 2 次素材失败 → 顶部提示条 + 一键切 `/lite`（**不自动跳转**）；
- kiosk 走 IndexedDB 缓存，断网显示"离线模式"角标。

## 4. 跨域与鉴权口径

| 项 | A | B | C |
|---|---|---|---|
| 凭证 | `Authorization: Bearer` | 同 A | 访客无凭证；kiosk 带 `X-Device-Code/X-Device-Token` |
| CORS | 不跨域（同站反代） | 允许 `m.xxx.edu.cn`，禁 Cookie | 允许 `exh.xxx.edu.cn`，禁 Cookie |
| 令牌存储 | Cookie（HttpOnly） | localStorage | 内存 + sessionStorage |
| 刷新 | 沿用 RuoYi 无感刷新 | 401 → 静默重登一次 | 设备令牌 401 → 提示"设备未授权" |

**必须避免**：B/C 复用 A 的登录接口返回的同一 Cookie 域，否则公网端会携带内网会话，测评时被判定为跨边界。

## 5. 视觉基线

> **前提**：需求文档 V3.0 未定义配色、字体、间距（全文检索"配色/色值/主色/品牌色/设计规范/样式规范/字体"均 0 命中，仅 EL-02-03 提到"字号调节与夜间模式"）。
> 所以视觉基线不自行发明：直接继承 A 端既有实现，三端同源。若客户后续提供 VI 或设计稿，以其为准，只需替换下表变量。

| 语义 | 值 | 来源 | 用在 |
|---|---|---|---|
| 主色 | `#409EFF` | Element UI 主题色（A 端全站按钮/链接在用） | 主按钮、链接、选中态、展区热点 |
| 副色 | `#3A71A8` | `legalTraining-ui/src/assets/styles/variables.scss` 的 `$light-blue` | 渐变、次级强调 |
| 深底 | `#141824` | RuoYi 深色主题的子菜单背景 | 展厅整页底色、登录页 |
| 面板 | `#1A1F2E` | RuoYi 深色主题的侧栏背景 | 卡片、浮层、播放区 |
| 正文 / 次要 | `#EEF1F6` / `#9AA4B2` | 深底上的可读反色 | 展厅正文与辅助说明 |
| 危险 / 警示 | `#C03639` / `#FEC171` | variables.scss 的 `$red` / `$yellow` | 下线提示、离线角标 |

使用规则：

1. **展厅端只写 CSS 变量 `--ex-*`**，不写死色值；换肤改 `lt-exhibit/src/styles/base.css` 的 `:root` 一处即可，预览页 `preview/zone-web.html` 同步同一组变量。
2. **A 端不动**，继续用 Element 主题（`element-variables.scss`）；B 端 Vant 用 `--van-primary-color: #409EFF` 覆盖，保证三端主色一致。
3. **状态色不另立**：任务/提交/展项状态的颜色取 `sys_dict_data` 的 `list_class`（primary/success/info/warning/danger），页面不自定义。
4. 需要新增语义色时先加变量再引用，禁止在组件里直接写十六进制。

## 6. 构建与发布

| 工程 | 构建命令 | 产物 | 发布 |
|---|---|---|---|
| A | `npm run build:prod` | `legalTraining-ui/dist` | Nginx 内网静态目录，`/api` 反代到 D |
| B | `pnpm build` | `lt-student-h5/dist` | CDN + Nginx，`/api` 反代 |
| C | `pnpm build` | `lt-exhibit/dist` | CDN（`index.html` 不缓存，`assets` 强缓存），素材单独 CDN 域名 |
| D | `mvn -DskipTests package` | `legalTraining-admin.jar` | systemd / Docker，profile=`prod` |

发布检查（每次）：
1. C 发版后刷新 CDN 的 `/index.html` 与 `/api/openapi` 缓存键；
2. B/C 的 `CORS` 白名单在 D 的 `application-prod.yml` 中固定为两个域名，不用通配；
3. A 的菜单变更走数据库，不随前端发版。

## 7. 开发启动顺序（本地）

```bash
# 1) 建库（单库版，开发机用）
mysql -u root -p < sql/legalTraining.sql
mysql -u root -p legal_training < sql/biz_schema.sql
mysql -u root -p legal_training < sql/biz_seed.sql

# 2) 后端（默认 8080）
mvn -pl legalTraining-admin -am spring-boot:run

# 3) A（8081，代理到 8080）
cd legalTraining-ui && npm run dev

# 4) B（5173）
cd lt-student-h5 && pnpm i && pnpm dev

# 5) C（5174）
cd lt-exhibit && pnpm i && pnpm dev
```

B/C 本地开发时 `VITE_API_BASE=http://localhost:8080`，需在 D 的 `application-dev.yml` 的 CORS 白名单里加 `localhost:5173`、`localhost:5174`。
