## SQL 种子脚本告警修复（sql/biz_seed.sql）

- MySQL 8.0.20+ 的 `[1287] VALUES function is deprecated`：4 处 `INSERT ... ON DUPLICATE KEY UPDATE col = VALUES(col)` 全改为别名写法 `...) AS alias ON DUPLICATE KEY UPDATE col = alias.col`（字典类型 new_dict / 角色 new_role / 通知模板 new_tpl / 系统参数 new_cfg）。注意别名语法要求 MySQL ≥ 8.0.19。
- DataGrip 的 `Unsafe query: 'Delete' without 'where'` 来自 `DELETE FROM edu_grade_level;`（种子全量重建，有意为之）。`-- noinspection` 注释对执行期警告无效，改为 `DELETE FROM edu_grade_level WHERE 1=1;` 消除提示。

## 保存资源报 Long 反序列化数组错误

- 现象：新增资源点保存，后端报 `Cannot deserialize value of type java.lang.Long from Array value`。
- 根因：Element UI 2.15 的 `el-cascader` 中 `emitPath` 是 `props` 配置项，**不是组件级 prop**；之前写在组件上的 `:emit-path="false"` 被忽略，v-model 一直是 `[父ID, 子ID]` 路径数组，提交给 `categoryId`（Long）即报错。
- 修复：页面 `categoryProps` 加入 `emitPath: false`；`BusinessRecords` 增加 `scalarValue` 归一化，提交与列表筛选时对 cascader 值统一取末级 ID（兜底兼容数组/标量两种形态），必填校验补上空数组判断。
- 验证：前端构建通过。坑记法：cascader 的 `checkStrictly`/`emitPath` 都要写在传给组件的 `props` 对象里。
